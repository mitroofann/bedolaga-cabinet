```markdown
Привет! Нужно добавить эндпоинты для управления автопродлением и сохранёнными картами пользователей в админской части. Это форк, делаем merge-safe реализацию.

## Контекст

Фронтенд уже обновлён с новыми API вызовами. Вот типы и endpoints которые нужно реализовать:

### Типы данных

```typescript
interface SavedPaymentCard {
  id: string;
  card_type: string;  // visa, mastercard, mir и т.д.
  last4: string;      // последние 4 цифры
  expires_month: number;
  expires_year: number;
  is_default: boolean;
  created_at: string; // ISO datetime
}

interface UserSubscriptionInfo {
  // ... существующие поля ...
  autopay_enabled: boolean;
  autopay_days_before: number | null;
  saved_cards: SavedPaymentCard[];
}
```

### Необходимые API endpoints

1. **POST /cabinet/admin/users/{userId}/subscriptions/{subId}/disable-autopay**
   - Отключает автопродление для конкретной подписки пользователя
   - Проверяет права доступа (только админ)
   - Возвращает `{ success: true, message: "..." }`
   - Должен обновить поле `autopay_enabled = false` в подписке
   - Если используется Platega/платёжный шлюз - также отключить рекуррентные платежи на их стороне

2. **GET /cabinet/admin/users/{userId}/saved-cards**
   - Опциональный query параметр: `subscription_id`
   - Возвращает массив `SavedPaymentCard`
   - Данные берутся из платёжного шлюза (Platega/Lava или другой)
   - Если нет `subscription_id` - вернуть карты всех подписок пользователя

3. **DELETE /cabinet/admin/users/{userId}/saved-cards/{cardId}**
   - Опциональный query параметр: `subscription_id`
   - Удаляет сохранённую карту через API платёжного шлюза
   - Возвращает `{ success: true, message: "..." }`
   - Проверка прав доступа

## Требования

### Безопасность
- Все эндпоинты только для авторизованных админов
- Использовать существующую систему авторизации проекта
- Валидировать входные параметры

### Обработка ошибок
- Graceful handling ошибок от платёжных шлюзов
- Информативные сообщения об ошибках
- Логирование всех операций

### Интеграция с платёжными системами
- Platega (основной)
- Lava (резервный)
- Учесть что API может отличаться для разных шлюзов

## Merge-safe стратегия

Чтобы минимизировать конфликты при мерге апстрима:

1. **Создай отдельные файлы** для новых контроллеров/сервисов где возможно
2. **Используй существующие паттерны** авторизации и обработки ошибок проекта
3. **Не меняй существующие эндпоинты** - только добавляй новые
4. **Добавь логирование** для отладки
5. **Документируй** новые параметры конфигурации если они нужны

## Файлы которые нужно изменить/создать

Найди в кодовой базе:
- Админский роутер/контроллер пользователей (обычно `routes/admin/*.ts` или `controllers/admin/*.ts`)
- Сервис работы с платежами/подписками (`services/payment*.ts` или `services/subscription*.ts`)
- Middleware авторизации если нужно
- Конфигурацию платёжных шлюзов

## Ожидаемый результат

После реализации фронтенд сможет:
1. Показывать статус автопродления и отключать его
2. Загружать список сохранённых карт пользователя
3. Удалять сохранённые карты

Все изменения должны быть закоммичены с описанием что было сделано.
